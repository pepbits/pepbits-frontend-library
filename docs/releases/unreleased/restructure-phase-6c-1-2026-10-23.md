## Added and changed

ERP1 and ERP2 have separate header selection, navigation and scope. AI is off. Both expose **57 catalogue destinations across 20 template families**, for **114 static destinations**, plus preferences. ERP1 keeps in-page record editing. ERP2 adds **46 view, 44 create and 42 edit route patterns**, worklist-order previous/next and column reset/persistence. Unknown paths fail closed.

Keystone is configured over public WorklistPage, RecordPage, TemplateFields, FieldRows, EditableMatrix, TemplateReport, cards and charts. ERP-specific fields, lookup hydration, calculations and commands stay in the app. The unchanged `/reference-modules/{erp1,erp2}` API owns data, validation and authority. Scope keys include tenant, user, role, branch and module. Failed saves retain input and ambiguous identical retries retain operation identity. Preferences use one serialized accepted-revision path with tenant locks, allowed values and focus/policy refresh. Runtime catalogs come from the API; generated aliases are canonical key mappings, not a separate translation catalog.

- Shell: shared ApplicationProviders and settings services; healthcare now consumes these exports. The scrollable main region is keyboard focusable even on read-only dashboards.
- Patterns: scoped fetch/resource/memory/view-state helpers, with scope-change cancellation/fencing and hydration/serialized-write tests.

- Page engines: controlled FieldRows and EditableMatrix; optional report date/amount concepts and generic row identity/numeric formatting; optional personal views and row-open worklist behaviour; accessible column visibility controls; shared CSV/XLSX export helpers.
- I18n: compact financial and short-date preference formatters.

Each affected package README is updated. The shared integration launcher moves to tooling; healthcare keeps its existing environment contract. No other-demo runtime import is introduced.
