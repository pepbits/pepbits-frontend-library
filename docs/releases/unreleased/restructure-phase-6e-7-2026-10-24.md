## Changes and user impact

The main window composes session/sign-in, API preferences and tenant policy, runtime catalogs, the enterprise shell, tabs, split comparison, floating MDI frames/taskbar, dirty-close/module guards and address synchronization. The existing workspace navigation hook now retains a record deep link when crossing to a module whose landing page is that same record page. Cancelling an address-driven module change restores the active document's address and retains its values. Eight application-workspace cases plus the crossing-module regression cover these shared changes.

The shared integration launcher accepts `desktop`, serves its production web bundle with `vite preview`, and removes its own temporary API data/loaders after stopping its process groups. Other services retain their Next launcher. No generic renderer, preference store or auth client is copied into the app. Desktop records reuse public worklist/form/record engines and `ResourceScope`/`useFetch`; the overview and component examples are demo-owned composition.

## Data, preferences and recovery

`VITE_API_URL` configures authenticated HTTP; missing configuration shows an alert. Optional `DESKTOP_API_URL` configures the dev/preview `/api` proxy. Session identity supplies tenant/user/role/branch. Worklists, layouts, personal views, exports and records use the unchanged API contracts and product ID `nexora`; no backend change or migration is introduced. Customer validation mirrors the existing API schema. Employee records and creation shortcuts narrow account grants; server authorization remains authoritative.

The shared record editor owns versions, operation identity, draft recovery and explicit retry. Failed saves retain typed values. Created customers reload by their generated record URL even when absent from the generated worklist. The worklist and record store are separate synthetic datasets; list synchronization after save and a broader durable draft contract are not claimed.

One accepted preference update path applies effective typography/scales, theme, radius, density, tables, page size, formatting, motion, shortcuts, tab mode and floating windows. Tenant locks override conflicting user choices, including mounted policy changes. Runtime localization uses protected canonical API catalogs; new desktop wording falls back to English.
