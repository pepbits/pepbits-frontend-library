## Decisions, preservation and completion boundary

The original areas are copied; protected sources remain unchanged. Data is below patterns, so shared designer/rule/catalog/lifecycle/v1 contracts are owned by data and re-exported by patterns. Minimal structural template field types and the original field renderer avoid importing page engines. The v1 contract bytes remain identical; existing dcp-fields exports remain exactly the original set. Designer and printing CSS modules/declarations are byte-identical. Markup, ARIA, ordinary keyboard controls, drag/drop sensors, collection identities, limits, recovery/conflict behavior and operation identity are retained, apart from the explicitly documented host/presentation differences.

All four workspace preference-prop interfaces move to the controlled PreferenceHost. Effective table settings/history size/formatting apply; managed form navigation overrides authored layouts and guards the layout selector. ScreenHost supplies designer/runtime dirty reporting and spreadsheet capabilities, notifications and transient rows. Read-only designer values follow effective formatting. Physical label stock remains server geometry. Standalone authoring state is not durable; DCP runtime drafts use the existing explicit DraftHost service.

Identity becomes `IdentitySubject`/`subjects`/`subjectId`, with explicit card/passport/biometric mode and required station. Devices require workbench/automation mode, station and host context choices. Label wristband selection becomes a host callback. Product page/category/context maps and subject data are excluded. Canonical localization keys such as `identity.patient` remain compatibility identifiers, with generic wording supplied by the host. The old product error class becomes `WorkflowRequestFailure`; structured errors retain status, fields and reference. HTTP factories formerly bound to product endpoints require explicit paths. The v1/codec runtime signatures, exact revision strings, validation/cancellation and explicit save behavior remain.

Spreadsheet product rows become empty defaults or host `initialRows`; product requests/classification become explicit audit/capability and operational column metadata. The original generic export-policy helper is copied with a structural column type to avoid an upward engine dependency. The same eight-column math, validation limits and value-free audit are retained. Effective CSV/XLSX export and presentation replace fixed filename/format/sticky/radius behavior. No data value is added to audit metadata.

Platform bridges only pass validated opaque tickets/results. Backend callbacks own consent, signature verification, authority and acknowledgement. Identity retains `authenticated: false`. Real successful authentication is not invented. Browser print dialogs remain browser operations; no Tauri/native/driver import exists. The showcase designer supports local draft save/preview; catalog writes and governance return an explicit host-required rejection. The reusable designer's full authoring/catalog/governance/runtime UI is included and tested with mocks.

Excluded code: four `library-page.tsx` launchers; `LABEL_PAGES`, `IDENTITY_PAGES`, `DEVICE_PAGES`; product subject/device/label/scan-context catalogs and spreadsheet rows; `createDcpRuntimeDemoAdapter` (product demo endpoint wrapper). No requested generic UI/config/adapter area is deferred. Source repeating helpers are inside `dcp-designer.ts`; no separate repeating implementation file exists. The parallel `demo-apps/healthcare` worktree is not read into the manifest or edited.

Dependencies retain the exact XLSX CDN `https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz`; DnD core 6.3.1, sortable 10.0.0 and utilities 3.2.2 match the source.
