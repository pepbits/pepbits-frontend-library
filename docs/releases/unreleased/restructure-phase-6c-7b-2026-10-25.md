## Changed behavior

The first seven transaction destinations in ERP1, then their ERP2 equivalents, now use a document-specific composition through the existing public engines: Sales orders, Sales invoices, Purchase orders, Goods receipts, Journal vouchers, Payment vouchers and Petty cash. This is **14 improved destinations, zero certified whole-destination matches**. All 38 transaction ledger rows retain exact differences; the other 24 remain deferred unchanged.

The subset provides four-column headers, compact typed line tables with footer totals, ERP1 300px / ERP2 320px summary/history rails, narration, tax-inclusive totals, effective-currency English amount words, status progression, copy-to-new and invoice preview (ERP1 selector, ERP2 selected invoice). ERP1 opens editable nonterminal documents in place and retains the filtered worklist with acknowledged refresh; ERP2 keeps view/edit/new routes. Copy resets identity/date/status. Empty documents cannot save. Positive debit/credit edits clear the opposite side and voucher progression requires a nonzero balance. Posted is terminal in the protected source, so no unreachable reversal action is invented. Cancellation follows the source terminal transition, including when filter options omit Cancelled. ERP1 requires balanced vouchers for any status transition, including cancellation; ERP2 permits cancellation of unbalanced vouchers. The API does not validate every status value.

Failed saves retain mounted input and operation identity; conflicts require Reload. Permissions, effective preferences and tenant locks remain authoritative. Density changes table/control dimensions, table wrapping/stripes/sticky headers stay managed, and form/result scales, formatting and radius follow the host. Document lines form one contiguous section and do not use worklist pagination. Closing/refresh warnings do not implement durable drafts. History reloads after accepted versions; Documents expands metadata. No API or source catalog changes.
