## Changes and user impact

Eighteen destinations have a source-derived composition update: Dashboard; Sales register, Purchase register, Stock summary, Receivables aging, Customer ledger and Invoice print; Company settings and Notification settings, in both ERP1 and ERP2. The [read-only source audit](evidence/restructure-phase-6c-7c-2026-10-25/source-audit.json) identifies the 24 scoped destinations, source files and measurement targets. Source JSX/CSS was inspected; the protected original desktop runtime was not rendered.

Dashboards gain 24px result-scaled KPI values, a 230px trend plot, a 140px status ring, inline range sparks and the source 12-column spans. The tooltip is available by pointer or keyboard selector. Status legend focus changes the center value. Analytical reports put compact source totals, average hints and colour markers above filters; ledger retains its strip below filters. Numeric cells align to the end and group/footer typography follows the source. Managed block padding takes precedence in both source and demo: 4/12/16px for compact/comfortable/spacious density. Recent-order dates use the source short-date formatter and customer cells retain the source 180px utility; the shared managed-table 36rem cap takes precedence in both source and demo, alongside managed wrapping. The source’s fixed 48px axis inset can clip long currency tick labels; the same preference-formatted amounts are retained, and this known source limitation is not a whole-page parity certificate. Invoice toolbar restores zoom icons/percentage and ERP1's 340px selector at the source breakpoint; A4 pagination is retained.

Settings use the source section arrangement through the public RecordSectionLayout and TemplateFields engines. Editing exposes Save changes and Discard; successful writes become the next discard baseline. Transient save failures retain inputs and operation IDs; conflicts require explicit Reload. Mounted permissions are checked before writes. Effective navigation, density, fonts/scales, motion, formatting, result view, table policies, export preference and tenant locks remain authoritative. Durable cross-route drafts remain unavailable; there is no ERP draft API contract.

Whole-destination exact matching is not certified. The ledger records specific remaining differences for every scoped destination: source-relative dashboard dates, skeletons and badge/ink styling; report toolbar and group/zero formatting; ledger statement composition; invoice selector/paper styling; settings active-rail strip/dirty-marker/save-bar/loading presentation. Both approval queues and all four user/number-series editors are unchanged and retain their existing workflow and geometry gaps. This is a verified composition subset when the checks below pass, not full phase completion.

## Library additions and compatibility

- Components: additive `TrendPlot`, `DonutSummary`, `RangeSparkline`, `MetricTile` through the new public `@pepbits/components/dashboard-visuals` subpath; existing defaults unchanged. Host labels, formatters and semantic tokens remain explicit. Direct tests cover inspection and empty/invalid data.
- Page engines: additive `data-column-type` metadata on TemplateReport headings/cells/footer; no default presentation or formatting change. ERP tests cover group/totals and numeric metadata.
- Icons: public `ZoomOut` re-export from the existing Lucide dependency.

Package READMEs document these contracts. No dependencies, package lock, backend schema or canonical catalog change. Rollback removes the additive frontend composition without data migration. Uncatalogued source English remains readable and needs human language review.
