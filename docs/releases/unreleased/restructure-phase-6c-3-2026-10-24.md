## Changes and user impact

The app keeps its existing shared host, API adapters, package boundaries and all 114 catalogue destinations plus the 132 ERP2 record/create/edit patterns. This increment changes **24 catalogue destinations**, listed in the [scope receipt](evidence/restructure-phase-6c-3-2026-10-24/scope.json).

- Four booking calendars: Appointments and Meeting rooms in both modules now render day/resource timelines. Day navigation, resource visibility, counts, upcoming list and Schedule/List switching use source configuration. Free slots supply date/resource/time to the existing editor. Creation checks the current selected day's overlaps; check-in, completion and cancellation are acknowledged commands. Failures preserve values and operation identity. Client overlap preflight is not an atomic server reservation guarantee; the protected backend remains authoritative for grants and record writes.
- Two invoice views: ERP1 selects beside the list; ERP2 opens its record URL. The document loads company/customer identity, bank details and terms from HTTP. Original/Duplicate, terms, zoom and isolated A4 printing use the source document structure, logo, columns and totals. Paper geometry/ink colors are deliberately fixed; selected font family/scale and date/amount formatting remain effective. The English amount-in-words block is labeled. Browser PDF verification does not certify a physical printer or exhaustive multi-page layout.
- Eight reports and two ledgers: periods/custom dates, source status/select filters, grouping, totals, preference-selected CSV/XLSX and ERP2 owner-record drill-down. Ledger opening/running/closing balances are calculated before text search; exports include the complete period statement. A truncated response suppresses totals and export instead of presenting a partial total as complete. Source reports have grouped lists and date filters, not an independent pivot designer.
- Six matrices: month, Monday-normalized week and term navigation; blank-only attendance fill; numeric bounds; row summaries and column totals. Sequential saves remove only acknowledged rows. Failed rows retain values and operation identity for retry; conflicts require explicit discard/reload. Period changes require Save or Discard. These are mounted drafts only.
- Two dashboards: all source response panels are composed, including KPI deltas/sparklines, combined sales/purchases, invoice status, orders, approvals, receivables and ticket/purchase shortcuts. Keyboard chart inspection and module-owned drill-downs are available. Source dashboards have no global data-filter API; chart controls inspect supplied data.
