## Added and changed

The resumed increment keeps the correct partial RecordPage/context work and completes personal worklist views without restructuring the app. Source record context covers 59 module/destination combinations: sixteen profiles; twenty document/voucher/structure destinations; four each for bookings, cases, requests and processes; two approval inboxes; two inspections; three ERP2 trees. States adds parent context/counts and parent-scoped creation defaults in both variants. All 114 catalogue routes remain.

Profiles show groups, statistics, changes/required fields, activity/documents and explicitly screen-local file choices. Booking detail/edit views show day/resource context, refetch when the date changes and disable related navigation while editing. ERP2 trees show cycle-safe breadcrumbs, children, Add child and confirmed leaf deletion, guarded for permissions, incomplete trees and non-leaves. Cases show conversations and stage/priority/assignee properties; movement history and replies use versioned commands. Approval context includes request amounts/dates/overdue state, attachments, route status and notes; ERP1 adds same-department related pending requests. Requests show balances/trails and decision notes. Document summaries calculate tax/deductions or debit/credit differences. Processes read support logs/steps; inspections show specifications and checked/pass/fail counts.

Support distinguishes loading, retryable failure and empty states, refreshing on acknowledged record versions. Comment failures retain input and retry identity; conflicts require explicit reload. Permission changes fence writes; effective shortcut settings govern Ctrl/Cmd+Enter. Formatting, density, typography, radius, table presentation, RTL and motion remain host preferences. No file upload/download service is invented.

**84 worklist destinations** add named filter/search/sort/column snapshots and column-only sets. Boards/calendars expose them in List mode. Existing source `{name,q,quick,filters}` views still apply; additive `snapshot` metadata retains typed criteria, column order and sort. Saving an existing name replaces it; Delete persists removal. The source API bounds apply: 30 views and 20,000 serialized characters. Remember filters selects account versus scoped session persistence; columnLayoutScope independently selects browser/account column storage. Account column keys are now correctly translated from visible engine keys to source hidden keys. Older 6c-1..6c-3 demo layouts may need Columns → Reset once: those builds wrote visible keys into the source hidden-key array, which has no version marker for safe heuristic migration. Order/sort are persisted by named snapshots; the API’s hidden-column array alone cannot retain them. Advanced filters cover multiple choices, text, dates, numeric ranges and booleans. Account failures remain visible with Retry. ERP view application preserves the current page size; the engine also guards locked/disallowed snapshot sizes.

- `@pepbits/page-engines/record-page`: optional summary/aside slots, responsive container placement and retained context across sections. Existing callers retain their form layout.

Package READMEs and tests cover these additions. ERP-specific metadata, source view-state mapping, panels and commands remain in the app. No dependency/version change or installation. School, desktop/backend/deployment/CI paths and the parallel session’s analytical/invoice files remain unchanged.
