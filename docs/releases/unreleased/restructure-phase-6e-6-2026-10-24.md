## Changes and user impact

Private `@pepbits-demo/allyvora-patients` adds an independent Next.js 16.3.3 / React 19.2 / Tailwind 4.1 app on default port 3400, with the same public ApplicationProviders chain as healthcare and ERP. `src/navigation.ts` owns navigation; `src/renderer.tsx` registers patient/layout kinds with the page renderer. `src/modules/registration` owns only AllyVora form configuration, orchestration and specialized presentation. AI is off.

| Destination | Source-compatible URL | Delivered behaviour |
| --- | --- | --- |
| Patient register | `/patients` | Five quick views/counts, search, sex/payer/branch filters, sorting, URL state, preference-sized table/cards |
| Registration | `/patients?mode=new` | Nine sections, 99 shared fields, conditions/defaults/rules, branch MRN preview, derived name, age hints, PIN autofill, dependent consultant choices, duplicates, signature/paper consent, rules drawer and validation jumps |
| Edit | `/patients?mode=edit&id=12&section=contact` | Same form and five arrangements, deep-linked section, versioned saves and retained input on 422/409/network failure |
| Record | `/patients?mode=view&id=12` | Wristband summary, section cards, masked identity values, missing details, activity, confirmed deactivation/reactivation and browser Print action |
| Layout designer | `/settings/layout` | Single page, tabs, guided steps, side steps, accordion; density/columns/summary/validation/draft settings, real-form preview, save/history/defaults/discard |
| Preferences | `/preferences` | Shared host preferences, tenant policy and runtime catalogs through one update path |

The root URL opens the register. Malformed IDs return to the register; unknown paths show not found. The persistent Next layout preserves module state between patient routes. Public CollectionView/Pagination, controls, Drawer/ConfirmDialog, recovery components and ScreenHost notifications replace copied primitives. AllyVora's fixed form definition and validation engine are consumed unchanged through its public `@allyvora/shared` package.

The DCP form-designer authors definitions and revisions; AllyVora's endpoint accepts six presentation settings for a fixed form. There is no compatible DCP authoring contract. Its layout chooser and five arrangements therefore remain specialized demo composition (CMP-04), sharing one field renderer and controller. The summary band, decorative barcode and section-status geometry likewise remain product presentation. No generic form-authoring engine is copied.

This resume retained the earlier implementation and fixed search text after browser navigation, obsolete asynchronous list responses, restored manual display names, controlled signature restoration/clearing, missing-canvas handling, and Tab focus after quick pick. Regression tests cover these behaviours. The browser driver additionally checks signature ink after draft restoration and quick-pick focus advancement.

## Data, preferences and failures

Patient data, lookups, numbering and layout history come over configured HTTP from the **unchanged AllyVora Express + SQLite backend**. The shared demo API supplies authentication, accepted preferences/tenant locks and localization. These require one instance of each API during integration, plus one Next server and Chromium. The app's server-only proxy origins and browser base URLs are configuration; components never construct service URLs. The adapter preserves the source error contract (`message`, 422 field errors, 409 current record), with retryable load errors and retained failed edits.

The AllyVora backend simulates identity as its first seeded user and does not enforce roles. The UI says whose identity is recorded in audit entries. Shell role checks are UI gating only: registration for administrator/operations/finance roles and layout changes for administrators. They are not backend authorization. No production identity or authorization claim is made.

Effective theme, fonts/scales, radius, table density/stripes/wrapping/sticky headers, result view, page size, date/time formats, motion and shortcuts use the shared host. Form arrangement/density are the source organisation settings. Native date inputs retain machine values. AllyVora-specific wording remains readable English where the protected canonical catalogs have no entry; Arabic direction and shared translations work, without implying complete translation or native-speaker approval.

New-registration drafts use public `@pepbits/patterns/resources` `useScopeMemory` as volatile **module memory** under the identity-keyed provider. They survive patient-route navigation, preserve chosen names/signatures when explicitly restored, and clear on reload, sign-out, identity/branch changes or Preferences/unknown routes. Form Back/Cancel asks before discarding; browser unload is guarded while dirty. There is no durable registration draft contract in the shared API. No patient values are persisted in browser storage. Cross-route edit recovery and universal shell-navigation leave confirmation are not claimed.
