# Healthcare Suite review disposition

The imported CarePoint services and the host adapter received a bounded, read-only Claude review with tools disabled. Session `886c6ecc-f1ed-43f9-83bd-e144c5a137ee` used Claude Sonnet 5. The original seven findings, prompt and session metadata are retained in `/tmp/healthcare-suite-api-evidence/claude-review.json`, `claude-prompt.txt`, `claude-review.stderr` and `claude-session-id.txt`. This document records the decisions against the actual source and final implementation; it does not claim that the reviewer independently verified the whole application.

| Finding | Disposition and evidence |
| --- | --- |
| 1. Facility should be bound to the host branch | The suggested `facility.branchId` check assumes a field the original CSV does not contain. Each trusted tenant/application/host-branch partition independently loads the two fictional source facilities. A selected facility is active in that partition and cannot replace host branch authority. The adapter rejects an unauthorized host branch before resolving a partition, and uses the selected facility for encounter creation. The session and partition-isolation tests cover host actor retention, invalid facilities, foreign branches and visibility of a new patient in another branch/tenant. See [facilities.csv](../../../dummy-api/reference-healthcare-suite-data/facilities.csv), [adapter](../../../dummy-api/reference-healthcare-suite-store.mjs) and the tests named `session retains authenticated host actor and branch-local selected facility`, `store enforces actor, product, role, module, branch and read-only writes`, and `partition identities isolate tenant, product and branch while sharing same branch data among actors` in [store tests](../../../dummy-api/reference-healthcare-suite-store.test.mjs). |
| 2. Stock guard used a second billing preview | Fixed. Aggregate item quantities are checked inside `BillingService.create()` using its single preview, before any order/stock/invoice mutation. The importer reproduces this patch. The test `aggregate repeated item stock cannot be oversold and failed invoice leaves every line unchanged` verifies rejection, unchanged stock and order status, and no invoice. See [billing service](../../../dummy-api/reference-healthcare-suite-source/billing/billing.service.mjs), [importer](../../../dummy-api/reference-healthcare-suite-import.mjs) and [store tests](../../../dummy-api/reference-healthcare-suite-store.test.mjs). |
| 3. Already-signed IDs return a fabricated sign response | Deliberate, documented source adaptation for safe retries, within the requested command-idempotency scope. The original service returns `{signed: count}`; a validated explicit list already in `Signed` state returns `{signed: 0}` with no additional effect. Each ID must belong to the encounter and be Draft or Signed. Fresh signing still delegates to the original service. Operation-key replay returns the original response after rechecking authorization. See [orders service](../../../dummy-api/reference-healthcare-suite-source/orders/orders.service.mjs), [adapter](../../../dummy-api/reference-healthcare-suite-store.mjs), [API contract](../../../dummy-api/reference-healthcare-suite-README.md) and the insured order/approval, invoice replay, and unsupported-shape tests in [store tests](../../../dummy-api/reference-healthcare-suite-store.test.mjs). |
| 4. Same-status appointment change bypasses source rejection | Deliberate no-op retry behavior. The source transition table has no self transitions; the adapter returns the current source record when the requested status is already current. It does not append the cancellation reason again or mutate state. Different-state commands continue through the source state machine. Same-status encounter commands and already-cancelled invoices follow the same policy. See [scheduling service](../../../dummy-api/reference-healthcare-suite-source/scheduling/scheduling.service.mjs), [adapter](../../../dummy-api/reference-healthcare-suite-store.mjs), [API contract](../../../dummy-api/reference-healthcare-suite-README.md) and scheduling/registration/cancellation tests in [store tests](../../../dummy-api/reference-healthcare-suite-store.test.mjs). |
| 5. Contract lines could forward extra keys | Fixed with explicit projection of `code`, `price`, `covered` and `priorAuth` before calling the original pricing service. That service also builds its persisted rows explicitly. Blank overrides with changed coverage/approval flags use the source contract's discounted default price. Validation and snapshot restoration prevent partial writes when a later line fails. See [adapter](../../../dummy-api/reference-healthcare-suite-store.mjs), [pricing service](../../../dummy-api/reference-healthcare-suite-source/pricing/pricing.service.mjs) and `contract editing is atomic and blank override uses discounted default with flags` in [store tests](../../../dummy-api/reference-healthcare-suite-store.test.mjs). |
| 6. Zero payment disappears from invoice creation | Retained source semantics. An initial zero payment row is an unfilled/default collection row, so creation filters it out and returns `payments: []`, `paid: 0`, an unpaid invoice and the full patient balance. This response never claims that a payment was recorded. Later collection requires an amount greater than zero and rejects zero with a field error. The test `invoice creation treats zero as an unfilled payment row while later collection requires positive payment` verifies both paths and unchanged payment records. See [billing service](../../../dummy-api/reference-healthcare-suite-source/billing/billing.service.mjs) and [store tests](../../../dummy-api/reference-healthcare-suite-store.test.mjs). |
| 7. Adapter guards duplicate source domain checks | Some overlap is intentional. The source services do not enforce trusted host authentication, module/product/branch access, actual actor stamping, selected-facility authority, operation replay or read-only permissions. Those checks belong to the host and reusable adapter. Additional ID/shape guards make explicit retry handling safe; ordinary business transitions/pricing/eligibility/billing still delegate to the imported services. Snapshot rollback protects partial failures. See [HTTP integration](../../../dummy-api/server.mjs), [adapter](../../../dummy-api/reference-healthcare-suite-store.mjs), [CSV adapter](../../../dummy-api/reference-healthcare-suite-source/common/csv-store.service.mjs) and [real HTTP tests](../../../dummy-api/reference-healthcare-suite-http.test.mjs). |

Acceptance uses real authenticated HTTP and browser requests, without fabricated UI actors or business-response interception. The localhost full browser run passed 40 checks: all 23 static routes, five source dynamic routes, header/session integration, patient registration, provider-slot appointment, linked encounter/check-in, catalog order/signing, invoice creation/collection, invoice URL, pharmacy selection and finance/School permission boundaries. Every consequential UI POST carried an operation identifier; there were no browser page errors. Evidence is retained in `/tmp/healthcare-suite-browser-final/results.json`, its screenshots and `/tmp/healthcare-suite-api-evidence/browser-final.log`. Earlier failed runs remain separate, including the populated encounter render error found during acceptance and fixed in the frontend. Focused HTTP/store results are retained in `/tmp/healthcare-suite-api-evidence/focused-review-final.log`; source provenance is in `provenance-check.json` and the [manifest](../../../dummy-api/reference-healthcare-suite-source-manifest.json).

These checks cover a fictional, process-lifetime application, not durable clinical records, real payer/eRx integration or regulatory/financial compliance. Original CSV dates and deterministic eligibility/approval simulations remain intact. In-memory partitions and operation replay disappear on API restart; no partition creates a timer or disk writer. Localhost acceptance does not establish public HTTPS deployment or unchanged legacy-module behavior; those require the delivery's separate production and regression runs.
