# Healthcare Suite fictional API

`server.mjs` exposes the original CarePoint contracts under `/reference-modules/healthcare-suite/api`. The caller signs in through the existing host. The response shape stays unwrapped, including `400 {statusCode,message,fields}` for source form validation. The frontend stores no fictional business data.

The source services are reproducibly ported from the original Nest TypeScript to dependency-free JavaScript with Node 24. The source hash manifest identifies every imported service, registry and CSV. Run `node dummy-api/reference-healthcare-suite-import.mjs /path/to/healthcare-suite/backend` to regenerate those files. The original source checkout is never modified. The small runtime and CSV adapter are hand-authored and retained separately from generated services.

Every source endpoint is implemented: session, dashboard and health; master worklists, records, create/update/status and lookups; patient search/detail/create/update with policies; resource slots and appointment book/reschedule/status/register; eligibility; encounter create/detail/status; catalog pricing, orders/add/update/cancel/sign and approvals; contract grids; billing queue/preview, invoice creation/search/detail, collection and cancellation. Original CSV headers supply text/number/boolean/JSON types and source key prefixes. Source business rules determine simulated eligibility, approvals, eRx, price-list defaults, consultation charges, deductible and copay cap, holds, split payments and invoice stock consumption/return.

Host authentication, navigation/module grants, product access and branch access run before the adapter. The adapter additionally rejects missing actors, unsupported roles, wrong products/modules, foreign branches and read-only writes. Enterprise administrators can use a permitted branch; operations roles can write in their authenticated branch; finance roles can read. The trusted host actor replaces source `U001` stamps for newly created appointments, encounters and invoices. `/session` returns that actor, never an actor requested with source query/body fields.

State is held in memory per `[tenantId, applicationId, branchId]`, shared by permitted users of that partition, and discarded when the process stops. Each partition contains its own two original demo facilities: a clinic and pharmacy. Facilities do not override branch authority. `X-Reference-Facility` selects an active partition-local facility and becomes the encounter facility; a contradictory encounter body facility is rejected. Worklists retain the original all-facility behavior within their partition. There is no invented branch/facility relationship to a real organization. No timer or disk writer is created for a partition.

`Idempotency-Key` is an optional operation identity (1–128 letters, digits, underscores, colons, periods or hyphens). Successful requests are retained for the process lifetime by actor/facility/key inside the partition. An exact retry returns its prior result; reuse for a different method, path, query or payload returns 409. The frontend transport supplies and retains keys across failed mutation retries. Retire a key after success so a deliberate subsequent order or payment remains a new operation. Registration, invoice cancellation, same-status changes and signing explicit already-signed order IDs are additionally safe on repeated calls. Unauthorized/read-only requests are rejected before any replay is returned.

The adapter rejects unsupported nested shapes, duplicate order identifiers, invalid numbers/date/time inputs, invalid billing categories and invalid payment modes/card references. Original master form numeric strings are still accepted and coerced by CSV schema. Failed commands restore the entire partition table snapshot, preventing partial contract, registration, encounter or stock mutations. Repeated item lines must fit aggregate stock consumption using the exact single preview used for invoice creation. Editing pending approvals is blocked; changing draft quantities resets obsolete eRx/prior approval references. Blank contract overrides retain the original default discount when coverage flags differ. Appointment cancellation requires the source UI's reason.

The API is a fictional, process-lifetime demo, with deterministic simulated payer responses. It does not provide real payer/eRx/identity integration, durable records, clinical documentation, claim submission or financial/clinical compliance. Source CSV dates remain unchanged; date-dependent seed behavior and payer eligibility retain their original finite validity dates. Tests use synthetic fixtures and their configured simulation delay.

Verify with the project Node 24:

```sh
node --test dummy-api/reference-healthcare-suite-store.test.mjs
node --test dummy-api/reference-healthcare-suite-http.test.mjs dummy-api/reference-modules-http.test.mjs
```

The store suite covers every master, patient validation/ownership, guest registration and scheduling, eligible/ineligible/manual payer paths, insured ordering/approvals/eRx, hospital and pharmacy billing/caps, payments/stock/idempotency, atomic failures, quantity reapproval, host actor and partition boundaries. HTTP tests exercise real host sessions, module/product/branch/read-only denials, source field errors, facility choice, replay, actor stamping and logout against an isolated dummy API process. Broader repository gates and browser tests are recorded by the integrated delivery, not inferred from these focused checks.
