# ERP parity handoff — phase 6c-4

The resumed increment delivers detailed record context and richer personal views on **84 worklist destinations**. All 114 destinations remain on the existing app/engines. The table identifies remaining work per destination; record/create/edit routes inherit the owning row. [Feature contract](../../docs/features/erp-demo.md) and [release record](../../docs/releases/unreleased/restructure-phase-6c-4-2026-10-24.md).

The source audit reads the protected ERP1/ERP2 templates and record components plus Keystone core. Account saved views retain the source `{name,q,quick,filters}` shape at `keystone.views.<slug>`, with additive `snapshot` metadata for sort, column sets and typed range conditions. Existing source views still apply. Columns use the source hidden-key representation at `keystone.cols.<slug>`. The API scopes state by tenant/application/branch/user and module transport; cache identity additionally includes role. Explicit named saves follow effective `rememberFilters`; column layouts follow `columnLayoutScope`. Saved views are not automatically applied on mount. The original source also applies them explicitly and holds sort in mounted state; named sort snapshots extend that behavior. Account requests have visible failure/retry. Same-name saves replace that named view; the API bounds are 30 views and 20,000 serialized characters.

**Draft audit:** none of the three source packages persists unsaved ERP business forms across routes or refresh. ERP2 `useUnsavedGuard` is only a `beforeunload` warning. That warning is now ported through public `useUnsavedWarning`; it does not guard SPA navigation or store values. Durable ERP form recovery remains unimplemented because the protected draft service accepts import/approval/DCP shapes and original page IDs, not an ERP form contract. Business drafts are not redirected to view-state or browser storage. This limitation applies to every editable destination listed below; it is not claimed as completed durability.

Activity/documents distinguish loading, failure/retry and empty states and refresh after an accepted record version. Local file choices remain explicitly unsaved metadata. All original-source screenshot/computed-style matching remains for the later visual session. Report/ledger/matrix controls, invoice pages and pagination are owned by parallel 6c-5 and untouched here. Lifecycle differences outside the three requested scope items remain recorded rather than silently called complete.
